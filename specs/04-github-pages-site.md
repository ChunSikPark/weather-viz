# Spec: GitHub Pages Site

## Job to Be Done

Host the visualization as a static site on GitHub Pages with proper structure and deployment configuration.

## Context

- Plain HTML/JS/CSS site — no build step required for the frontend.
- Data files are pre-computed and committed to the repo.
- The preprocessing script is a Python tool run locally (not in CI for simulation, but CI can run the preprocessing + deploy step).

## Requirements

### Repository Structure

```
weather-viz/
├── index.html              # Main page
├── css/
│   └── style.css
├── js/
│   ├── app.js              # Main application logic
│   ├── charts.js           # Plotly chart configurations
│   ├── map.js              # US choropleth map logic
│   └── data-loader.js      # Fetch and cache JSON data files
├── data/
│   ├── manifest.json       # Data inventory
│   ├── monthly/            # Monthly aggregated data
│   ├── daily/              # Daily aggregated data
│   └── hourly/             # Hourly data (recent 2 years)
├── scripts/
│   ├── preprocess.py       # CSV → aggregated JSON pipeline
│   └── requirements.txt    # Python dependencies
├── IMPLEMENTATION_PLAN.md
├── AGENTS.md
├── specs/
│   └── *.md
└── .github/
    └── workflows/
        └── deploy.yml      # GitHub Pages deployment
```

### Deployment

- GitHub Pages serves from the `main` branch root (or `/docs` folder if preferred).
- Deploy workflow triggers on push to `main`.
- No build step needed — just copy static files.

### Data Management

- Large data files should use Git LFS if they exceed GitHub's file size recommendations.
- Alternatively, data files are generated by the preprocessing script and committed directly.
- `.gitignore` excludes raw CSVs and intermediate files.

### Performance

- Use CDN links for Plotly.js and any other libraries (no local copies of large libs).
- Enable browser caching via appropriate file naming (content hashing for data files is a stretch goal).

## Acceptance Criteria

- Site is accessible at `https://{username}.github.io/weather-viz/`.
- All data files load correctly from the `/data/` path.
- Deployment succeeds automatically on push to main.
- Repository size stays under GitHub's recommended limits.
